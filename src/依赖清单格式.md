# 维护依赖信息

日常使用可以直接在“依赖安装 → 登记依赖”填写表单。需要批量维护或分享时，在同页导入、导出 JSON 清单。所有下载和说明入口仅打开网页；本页不运行第三方安装程序。

## 清单示例

以下地址是格式示例，请替换为作者的真实网页链接。

```json
{
  "schema_version": 1,
  "dependencies": [
    {
      "id": "example-bridge",
      "name": "示例电脑桥接",
      "kind": "桥接程序",
      "download_url": "https://example.com/bridge",
      "guide_url": "https://example.com/bridge/guide",
      "description": "为摆件应用提供电脑端数据。",
      "instructions": "根据作者说明自行下载安装，再填写电脑地址及端口。",
      "source": "作者使用说明"
    }
  ],
  "apps": [
    {
      "app_id": "example-app",
      "name": "示例摆件应用",
      "reviewed": true,
      "source": "用户维护",
      "requirements": [
        {"dependency_id": "example-bridge", "version": "1.x", "optional": false}
      ]
    }
  ]
}
```

- `app_id` 必须与摆件的软件标识一致。`id` 是依赖标识，同一组件使用同一标识，就会去重并共用人工准备状态。
- 标识支持字母、数字、下划线、点和连字符，最长 100 字符。
- `download_url` 与 `guide_url` 可以留空；填写时须为 HTTP/HTTPS 网页地址，不可包含账号密码。请优先维护官方或作者项目页面。
- `reviewed: true` 表示已经核对依赖资料；`requirements: []` 配合 `reviewed: true` 才表示确认无需外部电脑依赖。未提供资料时保持 `reviewed: false`。
- `optional: true` 表示该应用的可选依赖；`version` 是说明文字，不进行自动版本比对。
- `source: "用户维护"` 的应用关联不会被商店自动声明覆盖。通过原生表单保存时会自动设置该来源。
- 导入是按标识合并，已有记录中的未知字段会保留。当前清单修改前会自动备份；人工状态独立存放，导入不会导入或修改安装确认状态。
- 应用关联中的 `requirements` 数组以导入内容为准。删除关联可导入该应用的新数组；请勿仅为隐藏依赖而将应用标为无需依赖。

## 商店作者声明

商店目录格式为 `{ "items": [ ... ] }`。应用条目如明确提供 `pc_dependencies` 或 `desktop_dependencies` 数组，Cubic Desk 会登记电脑端依赖。例如：

```json
{
  "items": [
    {
      "app_id": "example-app",
      "name": "示例摆件应用",
      "kind": "app",
      "manifest_url": "https://example.com/app/manifest.json",
      "pc_dependencies": [
        {
          "id": "example-bridge",
          "name": "示例电脑桥接",
          "version": "1.x",
          "optional": false,
          "download_url": "https://example.com/bridge",
          "guide_url": "https://example.com/bridge/guide"
        }
      ]
    }
  ]
}
```

未声明电脑端依赖时显示“依赖信息待补充”。只有明确声明空数组才视为作者声明无需电脑端依赖。普通 `dependencies` 字段可能指设备端组件，因此不会自动当成电脑端依赖。

安装提示可以先跳转到依赖页面，也允许继续安装摆件应用，再手动准备电脑端组件。只有设备报告完成并在已安装列表中确认后，才显示设备应用安装成功。
